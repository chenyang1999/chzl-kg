2. 一份主决策到底怎么形成

以下按职责解释判断路径，不是声称每条思考义务都已经被代码强制或被真实模型履行。

顺序要回答的问题主要证据/职责输出去向与边界
① 市场背景市场在奖励什么？广度、涨停溢价、梯队、炸板及风格如何？R1、情绪/热度证据决定风险温度与预算上限；不预设“某情绪节点必配某打法”
② 主线与候选哪些方向有持续资金、叙事共振与辨识度核心？R2 消费 R3/R4；R7 提供资金证据形成主/次线和候选，不直接下单；概念池不等于纯度已核验
③ 个股证据候选的基本面、价格位置、股性、资金和事件能否支持参与？R5 对真实 R2 候选画像，图表只作其中证据分清产业逻辑与短期资金逻辑；缺数据保留缺口
④ 独立反证哪些假设被反证？哪些是不可覆盖的硬否决？R6 只读 R1—R5/R7大模型主决策须承接明确 hard_reject；建议项可解释取舍
⑤ 独立取舍谁只观察、谁可进入计划执行池、何时不能交易？D1 综合获准主研究输入执行池、观察池、拒绝原因、反向剧本及仓位；合法空执行池也正确
⑥ 行为条件符合/超/不及竞价预期怎么办？买卖触发及失效条件是什么？D1 计划规则；P1/P2 后续对照计划文本不是成交指令；未知执行谓词不能自动变成可执行条件
⑦ 权限兑现这个账户、这只票、这个报价和时点真的允许提交吗？loader、扫描、执行器、最终下单复核账户只能收紧，不能给计划补权限或把零预算改正数

术语保留用户定义：低吸是预判当日能涨停、相对涨停价仍低的强势参与，不等于大跌抄底；半路是平开后放量突破压力位跟随。本文不增设策略或参数。当前规则备用算法仍有按风格字符串选通道的固定映射，这只是该分支的实现，不能当作大模型主决策或用户方法论的完整实现。

主决策技能职责：skills/main_decision_v1/SKILL.md:208-311,339-481,1191-1240；规则备用分支：src/plan/d1_algorithm.py:254-353,731-990。

3. 三种“通过”必须拆开

flowchart TD
    A[产物存在] --> B{本次交付可验吗？<br/>日期 / 来源 / JSON / MD / run / attempt / 版本}
    B -- 否 --> STOP[标交付缺失或拒绝<br/>不能用旧文件冒充]
    B -- 是 --> C{研究是否就绪？<br/>缺研究 / 降级 / 需重评分别记录}
    C -- 明确未就绪 --> SAFE[只许安全临时版<br/>dry_run / 禁自主 / 需确认]
    C -- 有就绪证据 --> D{计划与账户都授权吗？}
    SAFE --> OBS[保留真实观察与待补证<br/>不自动获得新买许可]
    D -- 否 --> OBS
    D -- 是 --> E{逐票预算 / 合规 / 真实报价<br/>同日扫描 / 买点条件 / 最终复核}
    E -- 不满足 --> OBS
    E -- 满足 --> I[进入对应执行分支<br/>意图 / 订单 / 成交仍分账]
  • 交付：机器 JSON、人读 MD 与本次版本可核验；不能证明研究判断正确。
  • 研究就绪：显式未就绪必须保留安全限制；旧格式缺少就绪标记仍有兼容行为，不能写成“缺字段就已经证明就绪”。独立 paper 对买入要求更强的正向就绪证据。
  • 交易许可：计划与账户双授权、逐票开关及最终边界共同决定；--mode live、入池、资格 PASS、观察 promote 都不能单独授权。
  • 退出分支单独处理：买入预算为零/禁止新买不应抹掉合法存量退出；不把一个笼统“停机”框当成所有买卖行为完全相同。

依据：scripts/research/pipeline_artifacts.py:198-234；trading/load_plan.py:83-133,186-213；trading/execution_authorization.py:51-105；scripts/execute/run_paper_plan_once.py:81-106。

4. 主路径、安全网、规则降级：不要画成同一种决策

flowchart TD
    MAIN[06:10 全量研究与主决策] --> CHECK[主输入版本预检]
    CHECK --> LLM[D1 大模型生成]
    NET[08:50 安全网] --> EXIST{已有合法完整 LLM 交付？}
    EXIST -- 是且无重评要求 --> KEEP[保留；不重跑研究]
    EXIST -- 安全临时版需重评 --> NEW{重评输入是否更新且可用？}
    NEW -- 否 --> BLOCK[保持限制并报告阻塞]
    NEW -- 是 --> RETRY[独立重试 D1]
    EXIST -- 否 --> UP{上游就绪检查}
    UP -- 不满足 --> BLOCK
    UP -- 满足 --> RETRY
    RETRY --> OK{形成有效新 LLM 交付？}
    OK -- 是 --> PUB[检查 JSON / MD 并单向交接]
    OK -- 否 --> F{是否有必须保护的合法 LLM 决策？}
    F -- 有 --> BLOCK
    F -- 无且满足降级条件 --> RULE[显式 python_fallback<br/>不冒称大模型成功]
    LLM --> PUB

已见差异：主链每次 D1 前执行 --verify-inputs；安全网重试没有调用同一完整版本预检，普通初次检查重点是 R5/R6。安全临时版的重评有更严格时间/path/run 检查，但仍不能画成两入口完全同强度。

已见规则差异：规则分支对 R6 否决来源的汇合不如 summary 完整；缺参考价有旧 fallback；顶层决策来源和嵌套标签有不一致风险。不能说规则版与 LLM 等价，也不能用规则兜底掩盖主链失败。

依据：scripts/plan/ensure_watchlist_plan.py:116-176,241-301,324-381；src/plan/main_decision.py:258-350,393-401；src/plan/d1_algorithm.py:102-146,579-595。

6. 执行路径：文本条件不能自动变成市场判断

实际机器链：

正式计划 → 日期/schema/权限校验 → 单向 staging → 账户约束交集 → loaded → 同日扫描 → 会话证据 → 分派 → 最终下单复核。

层已实现的边界仍须明示的限制
计划加载正式源优先；不拿旧 runtime 绕过坏正式源；原子替换runtime-only 历史兼容仍存在，不能统一称所有消费者 canonical-only
预算与模式缺失计划预算不由账户补值；零值保持禁买；双边同意才可 liverisk_limits 只接收明确字段，未知键拒绝；不能删保护字段来“跑通”
买入资格实际拟提交价的盈亏比、来源/冲突/待复核检查PASS 是资格，不是独立许可
扫描与会话缺/异日/其他票扫描不能复用；新扫描先清旧成功缓存有规则类型不表示所有附加谓词都支持；未知条件及非零溢价约束可能 fail-closed
订单最终边界再核 kill、权限、日期、池、规则、预算、报价和数量不替代策略本身缺失的市场触发判断
卖出与买预算/买扫描分开；须合法可卖量与报价某些板块切换/量价背离条件实现仍不完整；另有低层精确触发/数量原反例未关闭

依据：trading/entry_selector.py:75-209；trading/watcher/session_context.py:21-87；trading/watcher/dispatch.py:76-149；trading/order/qmt_context.py:139-181,234-308；trading/executors/base.py:58-151。

两种模拟不要混：

  1. 当前 watcher cron 固定启动 --mode dry_run，受理/订单意图日志不能当成交。dry_run 也不天然保证所有路径离线，不应为写文档而调用它。
  2. scripts/execute/run_paper_plan_once.py 是独立账本单次 driver，需显式模拟授权、本地行情/日历、来源与就绪证明；与真实账户分账，也没有在本次任务清单中证明已自动调度。其结果区分 intents/orders/fills，不能拿第一种日志充第二种成交回执。

7. 审阅红点：本轮只记录，不借文档改行为

优先级红点收口要求，不是本次已完成
P0两个低层卖出触发/数量残余，以及跨进程提交/券商对账未认证保留原失败断言、关闭真实绕过；合法退出不受误阻；未经许可不碰真实账户
P1主链与安全网输入校验不同获准后统一版本/来源判定，覆盖旧文件/错 run/改稿拒绝场景
P1七类辅助输入仍待签；模型实际读取未证按窄来源政策另行授权；实际工具成功事件与采用/拒绝理由分别留证
P1P1/P2 自动应用未见先决定是否授权自动应用；实现需绑定原计划版本/时窗/预算与复核，不因报告有 promote 就升权
P1午盘取样口径、R7 增量生产/版本覆盖确认实际 producer、live 参数、来源日期和早午版本，保留真实降级
P1周五进化 17:00 早于日复盘 18:00报缺本周末日输入；调度变更另签，不在本轮挪时刻
P2周末 manifest 与重跑 manifest_intel 的固定读取可能错位对同日首次/重跑分别验消费者，不用旧 manifest 充新输入
P2股性月内重复能力及任务名/注释落后列精确消费者和差异再决定，不能由“重复”自动推出可删除

8. 实际证据链应当留哪四张收据

  1. 交付收据：谁在何业务日、何次运行/尝试交了哪个 JSON 和 MD，内容版本是什么。
  2. 传递收据：汇总及主决策获准读取清单指向哪些精确版本。
  3. 读取收据：真实模型成功读取这些版本的工具事件；不是仅有 skill 必读要求、Python 预检或文件路径。
  4. 裁决收据：采用/拒绝/延后/未读的理由及对应计划字段。自报采纳不是理解正确，理解也不是成交。

当前主输入前两层已有实现；后两层及辅助接线不能冒认闭环。历史工程回归与本次静态核对均不等于自然调度稳定、交易放行或账户盈利证明。
