## 二 · 根因分析(每条对应一条 Q)

### R1 · Q1 的根因: 板块表把"宽基/属性/通道"当"概念板块"塞进流出榜
- `tushare.moneyflow_ind_dc` 返回的板块列表里,以下标签**根本不是产业主题板块**,而是全市场标签或宽基:
  - **宽基指数类**: HS300_ · 上证50 · 中证500 · 创业板综 · 深证成指
  - **通道类**: 沪股通 · 深股通 · 富时罗素 · MSCI中国 · 标准普尔
  - **属性标签类**: 融资融券 · 大盘股 · 中盘股 · 小盘股 · 昨日高振幅 · 昨日高换手
  - **ST/次新类**: ST板块 · 次新股
- 这些"板块"覆盖 2000-4000 只股票,负数≈全市场资金流出的镜像值,**永远排在流出榜最前**。
- 流入端的先进封装 / 华为海思 / 氮化镓是**窄板块**(50-200 只),资金浓度有意义 → 所以流入准。

### R2 · Q2 的根因: 跷跷板算法**只看单日金额差**,没做多日滚动相关
- 检测代码目前把候选板块两两配对求"净流量反号 + 金额相近",但:
  1. 没先过滤宽基/属性标签(和 R1 同源),量级差 10-20 倍必配对失败
  2. 跷跷板本质是**趋势级负相关**(周级),不是单日金额匹配
  3. 现实场景: 创新药(防御链)+ 半导体(进攻链)近 5 日 rolling corr < -0.6 → 强跷跷板,当前算法完全捕捉不到

### R3 · Q3 的根因: ETF/期货维度数据取样极其贫瘠
- 当前只取 4 只 ETF 代表 → 全市场 ETF 900+ 只,采样率 0.4%,统计无意义
- 期货基差只给 1 个数字 -88.86,没标合约(IF/IH/IC/IM 当月次月共 8 个基差都该给)
- ETF 的"净流入"用 `份额 × 收盘价` 估算,不是真实一级市场申赎,方向可能反

### R4 · Q4/Q5/Q6 的根因: **MCP profile 隔离配错了 · 关键 MCP 只挂在 default profile,没同步到 canghai-* 各 profile**

诊断实测:
```
=== default profile MCP ===
  canghai-charts   ✓ enabled  ← chart_vision 在这里
  canghai-sise     ✓ enabled  ← 实时资金/tick 在这里
  xtick            ✓ enabled

=== canghai-research profile MCP ===
  tushareMcp datapro vibe-trading weflow-analytics
  ↑ 只有 4 个 · canghai-charts / canghai-sise / xtick 全部缺失

=== canghai-fetch profile MCP ===
  tushareMcp datapro vibe-trading weflow-analytics
  ↑ 同样缺失

=== canghai-execute profile MCP ===
  agentqmt_qmt xtick weflow-analytics
  ↑ 只有 xtick,没有 canghai-charts 也没有 canghai-sise
```

**结论**:
- `chart_vision` 之所以"总是不成功",因为**R5 sub-agent 跑在 canghai-research profile 下,该 profile 根本没挂 canghai-charts MCP**。上层 md 报告写"chart_vision DEGRADED" 是**永远 DEGRADED**,不是偶发。
- `canghai-sise` 全域 DOWN 同理: **canghai-research / canghai-fetch 都没挂 canghai-sise MCP**,自然全域降级。这不是 sise 服务挂了,是 profile 里根本没配。
- `iwencai` 的 hithink-* skills 需要通过 `hithink-*` MCP server 或 `iwencai-query` skill 调用。**canghai-research 的 mcp list 里没有 hithink 相关 server**,只有 tushare/datapro/vibe/weflow 四个。
- IWENCAI_API_KEY 环境变量已同步到 5 个 profile 的 .env(本轮修复),但**没有挂 hithink MCP server 也用不上**。

### R5 · Q7 的根因: 目前 R agent 只在每份 md 底部写"数据源审计"三色表,**没有一张跨 R1-R7 的全局表**

### R7 · Q9 的根因: fetch skill 抓取清单缺 3 源 · 硬红线永久不满足
实测 `data/raw/20260708/`:
- 只有 `manifest.json`(106B) + `mcp_health.json`(102B),两个空壳

- R4 skill 把这三源标记为"硬扩三源硬红线",但 fetch skill(`fetch_all_sources_v1`)里根本没抓这三个 → **每天 R4 永远 degraded**
- 且今晚是 22:00 时点,明早 07:00 才跑 20260708 fetch,所以现在整个 raw 目录是空的属于时序正常;但即便 07:00 跑完,news 三源缺失依旧

### R8 · Q10 的根因: R4 skill 只做"事件强度",**不做"事件×股价位置"耦合分析**
当前 R4 输出的每个事件只有: `strength/polarity/days_since/single_source`
缺失维度:
- **股价位置分位** `pos45` / `pos_120d` (低位/中位/高位)
- **利好利空 × 位置**的四象限解读矩阵:
  - **低位利好** → 启动信号 · 加仓 (最强)
  - **高位利好** → 兑现出货信号 · 观望或减仓 (陷阱)
  - **低位利空** → 恐慌见底 · 反向机会
  - **高位利空** → 补跌信号 · 硬止损
- 目前 R4 首推票分析是"事件驱动式"(有利好→买),完全不考虑"这个票已经涨了多少" → 会撞上"高位利好=出货"陷阱
- 颜晓滨警示的"高位科技借利好出货"其实就是**用户想让 R4 内化的能力**,但 R4 只是把颜晓滨的话作为"负面事件 E008"记下来,没把这个逻辑通用化到所有事件

### R9 · Q11 的根因: R4 skill 没有"宏观/板块层"事件聚合视图
当前 R4 输出是**逐事件+逐股**,缺:
- **宏观层**: 央行/统计局/税收/关税/外围市场对**大盘方向**的定性(利好/利空/中性)与影响力度
- **板块层**: 事件对**板块整体**的影响(现在只到"E001 华为韬定律 V2 → 中芯/长电"个股映射,没输出"整个先进封装板块的资金/情绪面向哪走")
- 结果是: D1 拿到的只有"票的清单",拿不到"今天大盘该防守还是进攻""板块整体强度多少"这样的**顶层判断**

## 六 · 关键判断沉淀(用户 review 显露的认知)

1. **"正确的废话"识别法**: 榜单 top 项如果**技术上必然如此**(全市场标签必然排负流出榜前),就是废话。
2. **"未检出" 是懒惰的**: 算法找不到就该改算法,不是产出"未检出"占位。至少给 top 3 弱结果 + 强度标注。
3. **数据源不足要显式承认**: "4 只 ETF 代表" 这种小样本推导结论,应该 disclaimer 而不是当成正常输出。
4. **"MCP DOWN"要区分**: 是**服务真挂了**还是**profile 根本没配**。今天的 chart / sise 全是后者,是配置 bug 不是服务故障。
5. **数据源审计要有全局表**: 每份 md 底部三色表是局部审计,用户要的是跨 R1-R7 的一张总表。
