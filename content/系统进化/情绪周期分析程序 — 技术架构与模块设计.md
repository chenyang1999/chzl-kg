## 一、架构总览

### 1\.1 设计原则

1. **单机优先**：用户本地运行，不引入数据库、消息队列等重型依赖。

2. **层间解耦**：标签引擎必须是纯函数，不得依赖数据源或外部状态。

3. **可测试优先**：核心判定逻辑（标签引擎）必须能在无网络、无 Tushare 的环境下被单元测试覆盖。

4. **渐进降级**：Tushare 不可用、积分不足、历史数据缺失时，程序不崩溃，自动降级并显式提示。

## 二、技术选型与 ADR

### ADR\-001：核心语言与数据处理栈

**状态：** Accepted

**决策：** Python 3\.10\+ \+ pandas \+ numpy

**理由：**

- 需求已确认为 Python 命令行 \+ 网页；pandas 是 A 股量化分析的事实标准；numpy 处理数值运算。

- 备选：Rust/Go 性能更好，但量化生态（Tushare、pandas、matplotlib）绑定 Python，切换成本不划算。

- 备选：Polars 比 pandas 快，但团队熟悉度低、Tushare 返回 pandas DataFrame 原生兼容，暂不引入。

### ADR\-002：网页层选型 — Streamlit

**状态：** Accepted

**决策：** Streamlit（而非 FastAPI \+ 前端框架）

**理由：**

|维度|Streamlit|FastAPI \+ React/Vue|
|---|---|---|
|本地启动|`streamlit run web.py` 一行搞定|需同时启前后端两个服务|
|开发成本|Python 写界面，无前端代码|需写 REST API \+ 前端组件|
|数据展示|原生支持 DataFrame、图表、指标卡片|需前端图表库 \+ 接口对接|
|定制性|中等，布局受限|高，可任意定制|
|部署复杂度|极低|中等|

**取舍：** 本期网页只做展示、无交互改规则、无用户登录。Streamlit 的「单命令启动 \+ 纯 Python 开发」完美匹配「用户本地运行简单」的硬性约束。若未来需要复杂交互或多人部署，再迁移至 FastAPI \+ 前端框架。

### ADR\-003：图表库 — Plotly

**状态：** Accepted

**决策：** Plotly（而非 matplotlib）

**理由：**

- Plotly 输出交互式 HTML，可直接嵌入 Streamlit 页面；matplotlib 静态图在网页中体验差。

- Streamlit 原生 `st.plotly_chart()` 支持。

- CLI 场景下 Plotly 也可导出静态 PNG，两用。

### ADR\-004：本地缓存格式 — JSON Lines

**状态：** Accepted

**决策：** 按交易日存储为 `.json` 文件（JSON Lines 用于批量序列）

**理由：**

- 人可读、可手动检查；Python 原生支持；比 CSV 更适合嵌套结构（如涨停明细列表）。

- 比 SQLite 轻量，不引入数据库依赖，符合单机优先原则。

- 增量更新天然支持：检查文件存在性即可。

#### 3\.2\.2 本地缓存（local\_cache\.py）

**缓存目录结构：**

```
~/.emotion_cycle/cache/
├── 2026/
│   ├── 20260901/
│   │   ├── limit_list.json
│   │   ├── daily.json

│   └── ...
├── 2025/
```

**缓存策略：**

- **写入：** 每次 Tushare 拉取成功后立即写入对应日期目录。

- **读取：** 优先读本地缓存；缓存不存在才调 Tushare。

- **增量更新：** 历史回放时，遍历日期范围，逐日检查 `os.path.exists()`，缺失日自动拉取。

- **缓存元数据：** 每个 `.json` 文件内嵌 `"_source": "tushare"` 或 `"_source": "daily_rebuild"`，用于追溯。

```python
class LocalCache:

    def write(self, trade_date: str, data_type: str, data: dict) -> None: ...

    def exists(self, trade_date: str, data_type: str) -> bool: ...

    def list_dates(self, year: int) -> list[str]: ...
```

**重建数据限制（需在输出中显式提示）：**

- 封单金额、首次封单时间缺失；

- 连板数为估计值，可能偏低；

- 炸板率计算可能偏低（因部分炸板特征无法从日线还原）。

### 3\.4 五档标签引擎（core/engine\.py）

**★ 核心约束：纯函数模块，不得依赖数据源、不得有副作用、不得读写文件/网络。★**

```python
    reason: str                        # 判定依据简述

    5. 低位试错：老题材冰点、新题材轮动、无主线 → 低位试错

    主跌 → 补跌 / 低位试错（连冰后修复）
    补跌 → 低位试错
    """

# ============ 置信度计算 ============

def _calc_confidence(indicators: DailyIndicators, tag: EmotionTag) -> str:
    """
    高：多项指标明确指向同一标签，无矛盾信号。
    中：主要指标指向该标签，但存在 1-2 项模糊或矛盾信号。
    低：指标互相矛盾，或处于两个阶段边界（如主升与高位震荡交界）。
    """
```

```
    │         │
    ↓         ↓
```

**仓位/手法规则表（直接来自需求文档第 2\.1 节）：**

|标签|指数同向|仓位|允许|禁止|
|---|---|---|---|---|
|低位试错|不同向|空到 1\-2 成|打首板；低位补涨；切新题材；轻仓试错|猛干高位龙；重仓|
|主升|同向|3\-5 成|干龙头；同题材补涨；低位潜伏；分歧敢买|支线；暗线；自己选的龙|
|高位震荡|任意|≤2 成|落袋、轻仓；龙头未死挖主线低位|博弈穿越当主仓|
|主跌|任意|空|空仓为主；连冰后尾盘试；切全新题材一日游|小反抽当主升；情绪票逆势|
|补跌|任意|空|尽量不碰情绪票|当超跌反弹满仓|

## 六、风险与降级路径

### 6\.1 Tushare 接口积分不足

|风险等级|高|
|---|---|
|触发条件|用户 token 积分 \< 120，`limit_list_d` 调用被拒|
|降级路径|1\. 提示积分不足；2\. 自动尝试 `daily` \+ `stk_limit` 重建；3\. 仍失败则进入离线演示模式|
|输出标注|`data_quality: "降级(积分不足，daily重建)"` 或 `data_quality: "离线演示"`|
|用户动作|充值 Tushare 积分 或 接受降级数据|

### 6\.2 2019 年数据缺失

|风险等级|中|
|---|---|
|触发条件|日期 \< 2020\-01\-01，`limit_list_d` 返回为空|
|降级路径|自动使用 `daily` \+ `stk_limit` 重建涨停/炸板/跌停名单|
|输出标注|`data_quality: "降级(daily重建)"`，并在 CLI / 网页显式提示重建限制|
|已知限制|封单金额缺失、连板数估计、炸板率可能偏低|

### 6\.3 网络失败 / Tushare 服务不可用

|风险等级|中|
|---|---|
|触发条件|请求超时、连接失败、Tushare 服务端返回错误|
|降级路径|1\. 重试 2 次（间隔 3 秒）；2\. 尝试本地缓存；3\. 无缓存则报错并提示检查网络|
|输出标注|使用缓存时 `data_quality: "降级(缓存)"`，标注缓存日期|

### 6\.4 极端行情指标失真

|风险等级|中|
|---|---|
|触发条件|千股跌停、全场普涨等极端日，常规指标边界模糊|
|降级路径|标签引擎输出 `confidence: "低"`，并附加 `transition_warning` 提示人工复核|
|输出标注|CLI 用黄色/红色高亮低置信度日；网页用警示卡片|

### 6\.5 总龙识别简化偏差

|风险等级|低|
|---|---|
|触发条件|程序简化版总龙识别（前 N 日高标 \+ 换手）与市场实际总龙不一致|
|降级路径|总龙开关仅作为「温度参考」，**不纳入标签引擎硬性判定条件**|
|输出标注|总龙状态旁标注「简化识别，仅供参考」|
