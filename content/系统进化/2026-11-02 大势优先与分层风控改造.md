## 三、逐项真相与证据

### 1. 资料质量、风险和权限分开

原始confidence及其计算事实保留，明确它不是盈利概率；不再让`confidence < 0.4`单独决定全市场禁买。辅助缺失说明影响，必要风险未知限制相关对象，真实全局硬风险及用户/账户限制按原作用域保留。

R1提出研究仓位建议，不批准账户额度。旧市场零仓建议必须有来源、事实时点和适用窗口，由合法计划owner依据本轮证据重新判断；真实用户/账户零预算或来源未知的保护不能被程序自动替换为正数。没有为更激进新增固定试仓比例或仓位下限。

研究提名、首次形成计划与实际执行分开。不能因新对象尚未进入旧计划就在研究阶段预先否决；执行仍须已发布计划身份、预算和独立许可。

### 2. 人气绑定不再混淆两个日期

允许既有`attention_signals_bound_v1`的自包含副本：使用日等于消费日，事实日和`signal_trade_date`相等且早于使用日；类型、schema、未来日和来源矛盾拒绝为具体辅助缺口。`source_path`只作来源说明，不获得打开历史文件的权限。

生产端新绑定明确自然日滞后口径`lag_basis=calendar_days`。旧绑定没有该口径时保留原声明，不擅自解释其计日单位，不把T-1事实日期改为当日盘中日期。

### 3. 日历要求与读取许可接通

## 四、前后对比

| 改前 | 改后 |
|---|---|
| 资料质量分低于固定值即可全局不开仓 | 原分数不变，按实际证据、必要风险与对象作判断 |
| 某票未审完或辅助缺项连带所有对象 | 必要缺证逐票列出，已完成对象独立比较 |
| 研究侧零仓意见被称为账户已批准上限 | 研究建议、用户/账户限制和未知来源保护分别说明 |
| T-1人气副本因顶层非今天被拒 | 严格核使用日与事实日的合法绑定，不改写事实 |
| 要审日历，但只允许两类快照 | 真实既有日历精确绑定，模型收到完整原文 |
| 新票不在旧计划即被预先拒绝 | 研究/形成计划身份与执行身份分开 |
| 统一昨收±5%和止损距离下限的旧说明 | 真实共享节点校验已接推导与消费，保留最大风险距离、原RR及实际开盘高开不追检查 |
| 只记买错，不记可执行机会遗漏 | 交易违规与真实可执行遗漏分账，不虚记实盘收益 |

## 五、根因

问题不是“数据必须完美”的单一口号，而是来源和作用域被压成了一个布尔开关：资料质量被当胜率，未完成工作被当已确认风险，研究仓位被当账户授权，观察池缺项被当所有执行对象不合格，形成计划又依赖自己尚未生成的身份。

此外，技能文字、真实生产者和消费代码没有一体维护：使用日/事实日语义冲突，日历读取义务没有对应白名单，价位旧伪代码与实际情景不一致。只加一句“更激进”或调低0.4无法解决这些循环。

## 六、改进与验收顺序

- **P0，工程已完成**：逐票必要审核消费、合法市场重评、输入接线和价位代码已按本批范围修复，主控联合回归通过；不另建研究平台或泛化评分，不再为同版代码重开审查。
- **P1，单列生产证据**：在正常任务中核新规则实际读取、逐票裁决与双件交付。代码绿测不认证模型已采用；本批不由主控手改今日正式预案买权。
- **P2，复盘效果**：量化因必要风险拒绝与因生产缺陷错失的不同原因，按当时可得信息和实际成交条件评价，不拿事后涨幅逼迫每天交易。
