# 反证 Agent Spec (R6 / analyze_devil_advocate_v1)

## 当前正式审核边界

必要风险逐票必审，辅助项目可局部降级：资金/消息交叉、风格一致性、出货风险及财务合规分别对应模式1必要分支、2、6、7；具体证据、窗口与完成标记以`skills/analyze_devil_advocate_v1/SKILL.md`当前正式范围为准。partial中的真实对象不因其他维度缺项而停止审核；缺必要证据仍未完成。

历史类比、昨日兑现、估值及其他辅助项目的缺口单列；仅辅助缺失不阻必要审核完成，但不隐去降级。高位本身不单独构成硬否决，原出货及财务合规硬否决仍保留。零反面发现、必要审核完成和允许交易不是同一结论；原有效零预算与执行门禁不变。

下文为早期方案与示例。其中“模式六唯一硬否决”“必须找够五条”“任何未确认即冲突”及按高度直接否决的旧表述不覆盖本节；不据旧例子补抓新数据、改变数值阈值或授予买权。

**归属**:第 6 个 Research Agent(在 D1 主决策之前跑)
**来源**:用户之前构思的 46 agent 表中的 #17 "魔鬼代言人 Agent",上一轮讨论我漏了,现在补上

## 1. 为什么需要反证 Agent

### 1.1 A 股协调游戏中的确认偏误陷阱

- R1-R5 的每个 Agent 都在积极找**支持某方向**的信号 → 天然倾向"验证"
- 但 A 股协调游戏本质是"多空博弈+主力反向操作" → **反面证据同样多**
- 如果没有一个 Agent 专门找反面证据,主决策会**系统性偏乐观**

**用户在 A 股活 5 年的关键**:不是"每次都对",而是**避免大错**。反证 Agent 的存在就是为了避免大错。

### 1.2 反证 Agent vs 传统风控

| 维度 | 传统风控 | 反证 Agent |
|------|---------|-----------|
| 时点 | 决策后审核 | 决策前挑战 |
| 逻辑 | 硬规则(仓位/ST) | 软推理(内在矛盾/历史类比) |
| 输出 | 通过/否决 | 5 个可能错的点 |
| 用途 | 阻断非法交易 | 修正决策偏差 |

**两者不冲突,都需要**:
- 反证 Agent = R6(研究端,决策前)
- 硬风控 = cursor 侧(执行前,已在 `docs/hermes-contract-reply-20260702.md` §11)

## 3. 反证的六类模式

### 3.1 模式一:数据源冲突

**触发**:两个及以上 α 层数据源给出冲突信号
```
例:
  - R3 WeFlow 说 A 板块热
  - R3 热榜说 A 板块霸榜出货
  - R4 公众号未提 A 板块
结论:  A 板块存在数据源分歧,建议降级为观察池
```

### 3.2 模式二:一致性检查(Agent 之间矛盾)

**触发**:两个 Research Agent 的结论逻辑上矛盾
```
例:
  - R1 风格判断:防御(建议减仓 + 只做龙一)
  - R2 主线核心票推 5 只中小市值 + 高波动
矛盾:  防御风格 vs 高波动票,内在冲突
建议:  要么修正 R1,要么修正 R2 —— 交 D1 主决策处理
```

### 3.3 模式三:估值 × 主线的临界

**触发**:R5 深挖发现估值偏贵 vs R2 主线核心
```
例:
  - R2 说宁德时代是锂电主线核心
  - R5 画像:动态 PE 45x,>历史 90%分位
建议:  仓位从 15% 降至 10%,或转为半仓 + 上涨补仓策略
备注:  A 股高估值可以走很久,不是必然错,标为 medium
```

### 3.4 模式四:历史类比

**触发**:当前形态与历史某个"最终失败"的形态高度相似
```
例:
  - 当前:板块连涨 5 日 + 龙头 20cm 涨停 + 热榜霸榜 + WeFlow 全群共振
  - 历史类比:2024-08 某板块 5 日后回撤 30%
  - 历史类比:2025-11 某板块 3 日后炸板
建议:  给 D1 一个"高潮警示",不否决,但要求出现某信号后强制减仓
```

**依赖**:需要历史事件库(未来 E2 周度进化沉淀)。v1 阶段人工填充 3-5 个经典案例。

### 3.5 模式五:昨日预期错误的连锁

**触发**:昨日 R6 反证的点,今日已被证实/证伪
```
例:
  - 昨日 R6 说三花智控出货,今日实际 -6.5% → 反证成功
  - 相似结构的票今日 R2 又推了 → **警报**
建议:  拒绝相似结构的票进 execution_pool
```

**依赖**:观察池追踪(见 `docs/05-专题-观察票追踪.md`)。

### 3.6 模式六:霸榜/极端信号硬约束

**触发**:R2 核心票命中 `distribution_alert` 高置信度
```
硬规则:  距离 R2 主线核心池强制降级到 watch_pool + reason = distribution_alert
覆盖:    R2 的结论(R6 拥有覆盖权)
仅限:    此单一模式,其他模式只是建议不是强制
```

**这是 R6 唯一有"强制否决权"的模式**,其他模式只是抛出证据。

## 6. 反证质量评估

### 6.1 每周计算 R6 兑现率

E2 周度进化每周五算:
- 本周 R6 强制否决的票:命中率 = 已兑现下跌 / 总数
- 本周 R6 建议修正的票:命中率
- 兑现率 <50% → R6 逻辑需要修正
- 兑现率 >80% → R6 可以扩权(某些模式从 soft 升级到 hard)

### 6.2 v1 阶段的初始阈值

**只有模式六(霸榜出货)默认有 hard_reject 权**。

其他模式 v1 阶段都是 soft/strong,累计 4 周兑现率 >70% 后 review 是否升级为 hard。

## 7. R6 的红线

1. ❌ R6 不许抓新数据(只读 R1-R5 产出 + 昨日复盘)
2. ❌ R6 不许给正向结论("我觉得 X 会涨") —— 只给反面证据
3. ❌ R6 不许否决所有票(必须留出至少 3 只候选,否则 D1 无法出预案)
4. ❌ R6 除模式六外不许硬否决(v1 阶段只有出货警报是 hard)
5. ✅ R6 必须每天出产出,即使全绿(全绿时输出 "今日无重大反面证据")

## 8. 与旧架构 risk_manager 的区别

| 维度 | risk_manager(旧) | R6 反证(新) |
|------|-------------------|---------------|
| 时点 | 决策后 | 决策前 |
| 逻辑 | 硬规则(单票≤15% ST 禁买) | 软推理(估值/矛盾/历史类比) |
| 生效 | 交易端 cursor 侧 | 研究端 D1 主决策 |
| 未来去向 | 归入 cursor 侧交易执行契约 | 保留在研究端 |

**risk_manager skill 将拆分**:
- 硬规则部分(仓位/ST/退市)→ 归入 cursor 侧 `docs/hermes-contract-reply-20260702.md` 的执行契约
- 软规则部分 → 归入 R6 反证 skill
